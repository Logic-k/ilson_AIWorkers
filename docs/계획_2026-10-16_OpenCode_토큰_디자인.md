## 0. 세 줄 요약

1. **OpenCode를 5번째 구독 엔진으로 추가**한다. 기본 모델은 `opencode/deepseek-v4.1-flash-free`(무료·200K 컨텍스트). 이 PC에 OpenCode 1.18.32가 이미 설치되어 있고, OpenCode 자체 공급자 자격은 아직 없다. 무료 모델은 **자격 없이도 동작하는 경로**(소스 확인)가 있어 "API 키 0개" 원칙과 가장 잘 맞는다.

3. **디자인은 라이브러리 대신 규율로** 끌어올린다. Paperclip의 DESIGN.md 방식(토큰 단일 소스·상태 세트 하나·기계값 monospace), agents-office/Pixel Agents의 사무실 연출 패턴(발밑 상태 링·게이트 말풍선·결정적 소품), 사장님이 본 릴스의 앱(bagidea-office로 추정)의 경험(inbox 결재함·묻기/안 묻기 스위치·예산 상한·직원별 모델 칩)을 옮기고, CC0 에셋만 쓴다. 추가 의존성은 `lucide-react`, `pretendard`, (선택) `sonner`까지.

## 1. 전제와 변경 불가 원칙

- **API 키 경로를 만들지 않는다.** 자식 프로세스에서 API 키 환경 변수를 지우고, 로그인 정보·토큰 파일을 읽지 않는다. (메모리: `subscription-only-no-api-keys`)
- **엔진별 자동 실행 동의는 사장님이 직접** 체크한다. 실행자가 설정 DB를 건드려 동의를 켜지 않는다.
- 기본 실행 방식은 **안전 모드**다. 자동 모드는 동의한 엔진만.
- 안전 모드의 지시서·에이전트 정의 방식(`.ilson/TASK.md`, `.agents/agents/`, `.claude/agents/`)을 OpenCode에도 같은 모양으로 확장한다.
- 이 세션에서 PowerShell·Bash 첫 실행이 2분 넘게 걸렸다(프로필 초기화 추정). **긴 명령은 `run_in_background`로 돌리고 결과 파일을 읽는다.** ripgrep도 `src` 전체 검색에서 20초 타임아웃이 났으니 경로를 좁혀 검색한다.

### A-3. 실행 전 사장님 확인 1회 (실행자가 요청)

1. (권장) 1.x 최신으로: `npm i -g opencode-ai@latest` → 1.19.x. **`opencode upgrade --major`는 실행하지 않는다**(2.x로 넘어감).
2. 빈 임시 폴더에서 무료 모델 1회 실행해 **실제 이벤트 형식을 캡처**한다(무료 한도 소량 사용 — 사장님 동의 후). 사용자의 전역 플러그인이 섞이지 않도록 `--pure`를 붙인다:
   ```bash
   opencode --pure run --format json -m opencode/deepseek-v4.1-flash-free --title "일손 테스트" "한 줄로 인사만 해 주세요"
   ```
   출력 줄을 `src-tauri/src/engine.rs` 테스트 픽스처로 쓴다(세션 ID 등은 줄여서). 자격 없이 동작하는지(= 콘솔 키 없이 성공하는지)도 이때 확인된다. `Free usage exceeded`가 나오면 §9에 기록하고 Go 모델 ID로 대체 경로를 안내한다.
3. 권한 자동 거부 형식 캡처: `OPENCODE_PERMISSION={"bash":"deny"}` 상태에서 "현재 폴더 파일 목록을 셸 명령으로 보여 줘" 한 번 → `auto-rejecting` 줄의 정확한 문구를 `denied` 파서에 반영.

## 4. 작업 B — 토큰·비용 계산기

### B-0. 용어와 결정

- **환산 비용**: 같은 토큰을 API 정가로 샀다면 들었을 금액(USD·KRW). **실제 결제**: 구독 범위 안이면 0원. 화면에는 항상 두 값을 나란히 쓴다("환산 ₩182 · 실제 결제 0원").
- 추정은 **휴리스틱 + 이력 보정**으로 시작한다. 정확 토크나이저(`tiktoken-rs` o200k, `tokenizers` + DeepSeek V4 tokenizer.json)는 바이너리 크기·빌드 시간이 커서 **2차 과제**로 미룬다. Claude·Gemini는 토크나이저가 비공개라 어차피 휴리스틱이다.
- 가격표는 **앱에 내장**(네트워크 없이 동작)하고, 갱신은 스크립트로 한다. 런타임 네트워크는 환율 갱신 버튼(선택)만.
- 구독 한도 조회는 **사장님이 버튼을 눌렀을 때만** 실행하고 10분 캐시한다(Claude·Antigravity만 가능).

### B-1. 데이터

**`src-tauri/src/db.rs`** — 새 테이블(`open()`에서 `CREATE TABLE IF NOT EXISTS`, 멱등):
```sql
CREATE TABLE IF NOT EXISTS usage_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  step_key TEXT NOT NULL,
  actor TEXT NOT NULL,           -- 직원 id
  engine TEXT NOT NULL,          -- agy|claude|codex|opencode
  model TEXT,                    -- 실제 모델 id (없으면 설정/기본값, 출처는 model_source)
  model_source TEXT NOT NULL,    -- reported|settings|default
  input_tokens INTEGER NOT NULL DEFAULT 0,      -- 신규 입력(캐시 제외)
  cache_read_tokens INTEGER NOT NULL DEFAULT 0,
  cache_write_tokens INTEGER NOT NULL DEFAULT 0,
  output_tokens INTEGER NOT NULL DEFAULT 0,     -- 추론 포함
  reasoning_tokens INTEGER NOT NULL DEFAULT 0,  -- 참고용 부분집합
  reported_cost_usd REAL,        -- CLI가 보고한 값(claude total/modelUsage, opencode cost)
  est_cost_usd REAL NOT NULL DEFAULT 0,         -- 앱 가격표로 계산한 환산 비용
  price_version TEXT,            -- prices.json의 generated_at
  usd_krw REAL,                  -- 기록 시점 환율
  prompt_chars INTEGER,          -- 보정용: 보낸 프롬프트 글자 수
  est_input_tokens INTEGER,      -- 보정용: 실행 전 추정치
  duration_ms INTEGER,
  mode TEXT NOT NULL,            -- auto|safe (safe는 토큰 미상 → 0, est_cost 0)
  at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS usage_log_at ON usage_log(at);
CREATE INDEX IF NOT EXISTS usage_log_engine ON usage_log(engine, at);
```
- `tasks.cost_usd`의 의미를 "환산 비용 합"으로 바꾼다(스키마 그대로, `runner.rs`에서 `StepResult.cost_usd = est_cost_usd`를 넘긴다).
- `Settings`에 추가(`models.rs`, `api.ts`): `usd_krw: f64`(기본 1343.0), `fx_updated_at: Option<String>`, `plans: HashMap<String,String>`(엔진별 요금제: agy `pro|ultra5|ultra20`, claude `pro|max5|max20`, codex `plus|pro`, opencode `free|go|go_plus`; 비우면 "미설정").

### B-2. 백엔드 모듈

**`src-tauri/src/pricing.rs`** (신규)
- `include_str!("../resources/prices.json")` → `{ generated_at, source, models: { "<provider>/<id>": { input, output, cache_read, cache_write, context, output_limit } }, overrides: {...} }` (단가는 1M 토큰당 USD).
- `resolve(engine, model_id) -> Option<Price>`: 정규화 규칙
  - claude: `claude-opus-5-5` 등 그대로; `opus|sonnet|haiku` 별칭이 들어오면 가격표의 같은 계열 최신 ID.
  - codex: 설정 모델 없으면 기본 `gpt-6.1-sol`(상수, 주석에 "codex-cli 0.159.1+ 기본").
  - agy: `gemini-3.8-flash-high` 같이 `-high/-medium/-low` 접미사를 떼고 조회.
  - opencode: `opencode/` 또는 `opencode-go/` 접두어를 떼고, `-free` 접미어가 있으면 **환산 비용은 유료 형제 가격**, `list_cost`는 0.
- `cost(price, usage) = (input*p_in + cache_read*p_cr + cache_write*p_cw + output*p_out) / 1e6`.
- `scripts/update-prices.mjs`(Node): `https://models.dev/api.json`에서 provider `anthropic, openai, google, deepseek, opencode, opencode-go`의 모델만 추려 위 JSON으로 저장 + `overrides`(DeepSeek 피크 가격, Gemini 가격 인상 예정일 메모). 네트워크가 막히면 §2-2의 값으로 손으로 채운 초기 파일을 커밋한다. `package.json`에 `"prices": "node scripts/update-prices.mjs"`.

**`src-tauri/src/usage.rs`** (신규)
- `pub struct Usage { input, cache_read, cache_write, output, reasoning, reported_cost_usd: Option<f64>, duration_ms }` 와 `From<RunResult>`.
- `engine::RunResult` 확장: `cache_read_tokens, cache_write_tokens, reasoning_tokens, reported_cost_usd: Option<f64>, duration_ms`. 각 `Collector` 수정:
  - agy: `cache_read_tokens`, `thinking_tokens`; `input_tokens`는 **캐시 포함 값이므로** `input = input_tokens − cache_read_tokens`, `output = output_tokens`(thinking 포함 여부가 불확실하므로 지금처럼 더하지 말고 `reasoning`은 참고값으로만 저장 — 기존 테스트 `output_tokens == 3` 기대값을 `2`로 바꾼다).
  - claude: `modelUsage`가 있으면 모델별 합(서브에이전트 포함), 없으면 `usage`. `input`은 캐시 제외 값 그대로, `reported_cost_usd = total_cost_usd`.
  - codex: `input = input_tokens − cached_input_tokens`, `cache_read = cached_input_tokens`, `cache_write = cache_write_input_tokens ?? 0`, `output = output_tokens`, `reasoning = reasoning_output_tokens ?? 0`(기존 테스트의 `output_tokens == 7` 기대값을 `5`로).
  - opencode: §A-1 그대로.
- `record(conn, ctx, step_key, job, usage, model, model_source, est_input, prompt_chars) -> est_cost_usd`: `pricing::resolve` → `usage_log` INSERT → 값 반환. `workers::run_job()`에서 호출하고 `StepResult.cost_usd`에 넣는다. 안전 모드 `watch_external` 경로는 `mode="safe"`, 토큰 0으로 한 줄 남긴다(횟수 집계용).
- `summary(conn, range) -> Summary`: 범위 `today|7d|30d|all`. 합계(토큰 5종, est_usd, krw), 엔진별·모델별·직원별·일별 집계, 건수. SQL `GROUP BY`로 끝낸다.
- `estimate(conn, settings, employee_id, input) -> Estimate`:
  1. `workers::ai_request`(사무팀) 또는 개발팀은 `request` 본문 + 설계서 유무로 **프롬프트 글자 수**를 구한다. `plan()`을 호출하지 않고 `ai_request`를 `pub(crate)`로 열어 쓴다. 개발팀은 `persona + rules + request` 길이로 근사.
  2. 글자 분류 계수(글자당 토큰) — 초기값, 주석에 출처와 "보정 대상" 표기:

     | 분류 | agy(Gemini) | claude | codex(o200k) | opencode(DeepSeek) |
     |---|---|---|---|---|
     | 한글 음절·자모 | 0.58 | 1.05 | 0.65 | 0.90 |
     | 한자·가나 | 0.6 | 1.0 | 0.7 | 0.6 |
     | 라틴·숫자·공백·구두점 | 0.22 | 0.36 | 0.22 | 0.30 |
     | 코드 블록 안(``` 사이) | 0.30 | 0.48 | 0.30 | 0.33 |
  3. 엔진 오버헤드(시스템 프롬프트·도구 스키마) 초기값: agy 10,000 · claude 15,000 · codex 20,000 · opencode 6,000.
  4. **이력 보정**: 같은 `(engine, actor, step_key)`의 최근 10건에서 `median(input_tokens + cache_read_tokens) / est_input_tokens` 비율과 `median(output_tokens)`를 구해 적용. 이력이 3건 미만이면 휴리스틱만 쓰고 `basis = "heuristic"`, 아니면 `"history"`와 `samples` 수.
  5. 출력 토큰 기본값은 `ai_request`가 돌려주는 `_typical`(지금은 버려지는 세 번째 값)을 쓴다. 이 값을 반환 튜플에 포함시키도록 시그니처를 바꾼다.
  6. 결과: `{ prompt_chars, est_input, est_output, est_total, est_usd, est_krw, basis, samples, model, free: bool }`.

### B-5. 예산 상한 (bagidea-office의 money caps 이식)

릴스가 권한 "토큰 예산 걸어 두기"를 앱 기능으로 넣는다. 구독이라 실제 결제는 없지만, **환산 비용 또는 토큰 수**로 상한을 걸어 한도 소진을 막는다.
- `Settings`에 `budgets: { daily_tokens: Option<u64>, daily_krw: Option<i64>, per_engine: HashMap<engine, { daily_tokens, daily_krw }> }`. 기본값은 비움(상한 없음).
- 검사 시점: `runner.rs`가 AI 단계를 시작하기 **전**에 `usage::summary(today)`와 `estimate`를 합쳐 판단한다. 80% 이상이면 업무 기록에 경고 이벤트("오늘 OpenCode 예산 82% 사용")를 남기고 계속 진행, **100% 이상이면 그 단계 앞에서 `paused`로 멈추고** 이벤트 "예산 상한에 닿아 멈췄습니다. 내일 자정에 다시 열리거나, 연결 및 설정에서 상한을 올린 뒤 이어하기"를 남긴다. 실행 중인 단계는 끊지 않는다(bagidea와 같음).
- 안전 모드 단계는 토큰을 모르므로 검사하지 않는다.
- UI: 사용량 페이지 상단에 예산 게이지(오늘 사용/상한, 80% 주황·100% 빨강), 연결 및 설정에 상한 입력(토큰 또는 원화 중 하나). 홈 setup-banner와 같은 자리에 "예산 80% 도달" 배너.
- 테스트: 인메모리 DB에 usage 행을 넣고 상한 80%/100% 판단 함수가 경고/정지를 맞게 돌려주는지.

## 5. 작업 C — 디자인 발전 (오픈소스 패턴 이식)

### C-0. 결정

- 외부 UI 프레임워크(Tailwind·shadcn)는 **도입하지 않는다.** `styles.css` 한 파일 토큰 체계가 이미 있고, Paperclip류 프로젝트가 수렴한 조합(토큰 + Radix/Base UI + lucide)에서 **토큰과 규율만** 가져온다.
- 추가 의존성: `lucide-react`(아이콘, ISC), `pretendard`(폰트, OFL). 선택: `sonner`(토스트), `@base-ui/react`(모달 접근성). 차트·게이지는 손수 SVG.
- 사무실은 **SVG 치비를 유지**하고 연출 규칙을 보강한다. CC0 픽셀아트(JIK-A-4 MetroCity, agents-office 스킨)로의 교체는 C-5 선택 과제.
- 다크 모드는 이번 범위 밖(토큰만 다크 전환 가능하게 설계).

### C-1. `DESIGN.md` (저장소 루트, 신규) — 규율 문서

Paperclip DESIGN.md 방식으로 다음을 적고, 코드 리뷰 체크리스트로 쓴다.
1. **토큰 단일 소스**: 색·간격(4pt 배수 `--space-1..8`)·반경·그림자·모션(`--dur-fast 120ms`, `--dur 200ms`, `--ease`)·글꼴(`--font-sans: Pretendard Variable`, `--font-mono: ui-monospace, "Cascadia Mono", Consolas`)은 `styles.css :root`에서만 정의.
2. **상태 세트 하나**: `--status-running`(파랑) · `--status-waiting`(주황, 사장님 차례) · `--status-paused`(amber) · `--status-failed`(빨강) · `--status-done`(초록) · `--status-idle`(회색) · `--status-over`(사용량 80%↑ 주황, 100% 빨강). 업무 배지·직원 아바타 점·사무실 상태 링·사용량 게이지가 **같은 변수**를 쓴다.
3. **기계값은 monospace**: 토큰 수·금액·시각·커밋 해시·ID·모델 ID.
4. **용어 하나**: "업무"(작업·태스크 혼용 금지), "직원", "구독 엔진", "환산 비용 / 실제 결제", "사장님 차례".
5. **버튼은 동작명**: "병합하기", "실행했어요", "맡기기". "확인/OK" 금지.
6. **빈 상태는 다음 할 일을 말한다**("첫 업무를 맡기면 결과가 여기에 쌓입니다").
7. **대기 상태의 테이크오버**: 사장님 차례인 업무는 카드 전체가 주황 테두리, 다른 강조는 끈다.
8. 접근성: `prefers-reduced-motion`이면 걷기 대신 페이드, 모든 아이콘 버튼에 `aria-label`, 포커스 링 유지.
9. 아트·에셋 크레딧은 Help 페이지 "크레딧" 섹션에 적는다(CC0도 적어 둔다).

### C-2. 기반 교체

- **폰트**: `npm i pretendard` → `src/main.tsx`에서 `import "pretendard/dist/web/variable/pretendardvariable.css"`. 현재 `styles.css`는 Pretendard를 참조만 하고 번들하지 않아 Windows에서 맑은 고딕으로 표시된다. CSP `default-src 'self'`로 로컬 폰트 허용됨.
- **아이콘**: `npm i lucide-react`. `components/ui.tsx`의 `Icon` API(`name`, `size`)는 유지하고 내부를 lucide 컴포넌트 매핑으로 바꾼다(호출부 무수정). 새 이름: `gauge`, `coins`, `cpu`, `shield`.
- **토큰 레이어 정리**: `styles.css` 상단에 C-1의 변수들을 추가하고, 기존 `--ok/--warn/--bad/--info`를 상태 토큰의 별칭으로 남긴다(한 번에 치환하지 않는다).
- (선택) `sonner`로 토스트 교체: `store.toast` 시그니처는 유지.

### C-3. 사무실 연출 (OfficeScene.tsx, styles.css)

agents-office · Pixel Agents · PixelOffice · agent-virtual-office에서 가져오는 네 가지.
1. **발밑 상태 링**: 각 직원 `<g>`에 타원 링을 추가하고 색은 `--status-*`. 매핑: running→running, awaiting_approval→waiting(깜빡임), paused→paused, failed→failed, 완료 3초→done, 그 외 idle(링 숨김). 활동 라벨(typing/reading/running/thinking/talking)은 포즈로만 남긴다.
2. **게이트 말풍선 = 승인 진입점**: `awaiting_approval` 직원의 말풍선을 클릭하면 `navigate("work", taskId)`로 바로 간다. 말풍선에 "!" 아이콘과 게이트 종류(병합/직접 실행/파일 이동)를 적는다. 사장석 "결재 N" 배지는 유지.
3. **결정적 데스크 소품**: 직원 id 해시를 시드로 모니터 색·머그·화분·벽 포스터 중 2개를 고정 배치(PixelOffice 패턴). 같은 직원은 항상 같은 책상 모습.
4. **실시간 업무 채널 패널 정리**(OfficePage 우측 `feed`): AIMAX "OFFICE LIVE" 구성처럼 상단에 "대표 1 · AI 직원 N · 진행 N"을 두고, 항목은 아바타 + 라벨 + 상대 시각, 사장님 결정(승인/반려)은 다른 말풍선 스타일. 엔진 배지 색은 `engineHue`.
- 유휴 배회·이벤트는 지금처럼 드물게, 설정 토글은 다음 단계.

### C-4. 화면 구조

- **업무 상세 탭화**(WorkPage): `결과물 / 증빙 / 변경 내용 / 토큰 / 기록`. 증빙 탭에는 테스트 결과(소희 보고서의 "확인 방법"), 민혁 판정, 커밋 목록, 작업 공간 경로를 모아 Symphony의 proof-of-work처럼 보여 준다. 변경 내용 탭은 기존 DiffViewer. 토큰 탭은 B-3의 단계별 표.
- **결재함**(HomePage "사장님 차례" 카드 + OfficePage 결재함): 카드마다 게이트 종류 아이콘, 요약, "열기" 버튼. 승인/반려 기록은 이미 `task_events`에 남으므로 업무 상세 "기록" 탭에서 `사장님` 접두 이벤트만 필터하는 토글을 둔다(OpenWorker 감사 로그 패턴, 새 테이블 없음).
- **직원 카드**(EmployeesPage): 상단에 "소속 구독" 배지(엔진 라벨+모델, OpenCode는 "DeepSeek V4.1 Flash · 무료"), `costSummary` 문구를 엔진에 따라 동적으로("구독 포함 · 추가 요금 없음" / "무료 모델 · 한도는 OpenCode가 정함").
- **홈 hero**: 통계에 "이번 주 환산 비용"과 "실제 결제 0원"을 함께. 문구의 엔진 나열은 4개 → "Antigravity·Claude Code·Codex·OpenCode".
- **도움말**: FAQ(OpenCode, 환산 비용 뜻, 한도 조회가 사용량을 쓰는지), 크레딧 섹션.

### C-5. 선택 과제 (시간이 남을 때, 별도 커밋)

### C-7. 릴스 속 앱(bagidea-office)에서 가져올 것 — 우선순위

일손은 이미 "팀장(태오)에게 맡기면 팀원에게 나누는" 구조와 직원 페르소나를 갖고 있으므로, 릴스가 보여 준 **사장님 눈높이의 네 가지 경험**을 보강한다. 코드는 Godot/Node라 가져오지 않고 패턴만 옮긴다.
1. **결재함 = inbox** (C-4 결재함에 합침): "뭐가 기다리고 있고, 뭐가 안 읽혔는지"를 한 화면에. 홈 상단에 `사장님 차례 N · 새 결과 N`을 두고, 결과물을 열어 보면 "읽음"으로 표시(`tasks`에 `seen_at` 컬럼 추가, 완료 시 NULL → 열람 시 기록). 사무실 결과함 배지도 미열람 수로.
2. **묻지 않고 실행 vs 물어보기 스위치를 사장님 말로**: 연결 및 설정의 YOLO·권한 단계 표 위에 한 줄 토글 "돈 쓰거나 파일을 지우기 전에는 물어보기(기본 켜짐)"를 두고, 켜져 있으면 `Level::Yolo`를 쓰지 않고 외부 디렉터리·삭제성 명령을 deny 하는 지금 규칙을 그대로 유지한다는 설명을 붙인다. 새 로직은 없고 **설명 방식**만 릴스처럼 바꾼다.
3. **예산 상한 + 아침 요약**: B-5의 상한과 함께, 앱을 켤 때 어제 사용량·완료 업무·확인 대기 수를 홈 hero에 한 줄로("어제 직원들이 업무 3건을 끝냈고 토큰 41K를 썼어요").
4. **직원별 모델 카드**: 직원 카드와 사무실 선택 패널에 "소속 구독 · 모델" 칩(예: OpenCode · DeepSeek V4.1 Flash 무료)을 항상 표시. 릴스 프레임의 "직원 이름 + 모델 + working" 카드 형태를 따른다(C-4 직원 카드 항목과 같음).
5. **한 줄 브리프 ✨ Draft** (선택, C-5급): 업무 양식의 `request` 칸 옆 "한 줄만 적으면 직원이 양식을 채워 줘요" 버튼. 담당 직원 엔진으로 읽기 전용 1회 실행해 양식 초안(JSON)을 만든 뒤 사장님이 수정·확정. 구독 한도를 쓰므로 자동 모드 동의가 있는 엔진에서만 보인다.

### C-6. 수용 기준

- [ ] `DESIGN.md`가 있고, 새로 추가·수정한 컴포넌트가 상태 토큰과 monospace 규칙을 따른다(리뷰 체크).
- [ ] Windows에서 Pretendard가 실제 적용된다(개발자 도구 computed font).
- [ ] 아이콘 교체 후 모든 화면의 아이콘이 보인다(빠진 이름은 콘솔 경고 대신 빈 네모가 아닌 lucide `HelpCircle` 폴백).
- [ ] 사무실에서 사장님 차례 직원의 말풍선 클릭 → 업무 상세로 이동. 상태 링 색이 업무 배지 색과 같다.
- [ ] 업무 상세가 탭으로 나뉘고, 기존 기능(병합·diff·되돌리기·결과 저장)이 모두 동작한다.
- [ ] `prefers-reduced-motion: reduce`에서 걷기 애니메이션이 꺼진다.
- [ ] 결과물을 처음 열면 미열람 배지가 줄고(`seen_at`), 홈 hero에 어제 요약 한 줄이 나온다.

## 9. 확인 필요 (실행 중 §9에 추가 기록)

1. **릴스 속 앱 특정**: "팀워커"는 임의의 말로 확인됐고(§2-3), 릴스의 앱은 bagidea-office로 추정된다. 릴스가 말한 "유료 Pro 플랜"이 README에 없어 확정은 아니다. 디자인 결정은 bagidea-office의 **패턴**(inbox·park·예산 상한·한 줄 브리프)만 쓰므로 앱이 다른 것으로 밝혀져도 계획은 바뀌지 않는다. 사장님이 릴스 댓글로 받은 자료(브리핑 네 줄·저장소 링크)가 있으면 §2-3을 갱신한다.
2. 무료 모델이 **자격 없이** 실제로 동작하는지(§A-3 1회 실행으로 확정). 실패하면 콘솔 키 등록 안내로 전환.
3. `OPENCODE_CONFIG_DIR`가 전역 설정 폴더(`~/.config/opencode`)를 실제로 대체하는지, `--pure`가 oh-my-opencode 플러그인을 완전히 막는지(`opencode --pure debug config`로 확인). 안 되면 `OPENCODE_CONFIG` 파일 경로 방식으로 바꾼다. `models opencode --pure`가 40초 안에 끝나는지도 같이 본다.
4. Claude `/usage`의 `usage_report` 필드가 설치된 Claude Code 2.1.x에서 나오는지(Claude 로그인 후에만 확인 가능).
5. Gemini·Claude 한국어 토큰 계수는 소규모 표본 기반 추정이다. 실측 10건 뒤 표를 갱신한다. Codex·DeepSeek 열은 로컬에서 정확히 잴 수 있다(선택, 앱 코드와 무관): 이 PC의 Python 3.13에 `tokenizers`는 있고 `tiktoken`은 없다. `pip install tiktoken` 후 `o200k_base`로 샘플 프롬프트를 인코딩하고, `https://cdn.deepseek.com/api-docs/deepseek_v4_tokenizer.zip`을 **새 빈 폴더**에 풀어 `tokenizers`로 읽으면(다운로드 파일이 있는 폴더에서 인터프리터를 실행하지 말 것) 두 열을 실측값으로 바꿀 수 있다. 결과는 `scripts/measure-tokens.md`에 기록.
