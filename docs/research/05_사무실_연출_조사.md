### 1-2. 확인하지 못한 것 / 추론
- **움직이는 원본 영상은 공개된 곳에서 찾지 못함.** 페이지에 쓰인 `__poster__` 이미지 6개를 ImageDecoder로 열어 보니 모두 1프레임짜리 정지 이미지였음. 그래서 걷는 동작, 계단 이동, 경로가 어떻게 생겼는지는 직접 보지 못함.
- 유튜브 @메이크패밀리(구독자 1.6만, 동영상 911개)는 공개 목록에 영상 2개와 쇼츠 몇 개만 보이고 나머지는 회원 전용으로 보임. 사무실 영상은 없었음.
- 강사 Threads(https://www.threads.com/@naminsoo__ai)는 로그인하지 않으면 최근 글 몇 개만 보이고, 그중에 사무실 영상은 없었음.
- aimax.ai.kr에는 영상이 없음. 첫 화면 아래 "자동 시연 중" 카드만 돌아감(업무 탭 → 담당 직원 아바타 → 받게 될 결과). lounge.aimax.ai.kr는 교육 플랫폼임.
- **추론:** 사용자가 말한 "소개영상"은 위 B 화면을 움직이게 만든 영상일 가능성이 가장 높음. 근거는 세 가지임. 3층 단면도 구조, 계단, 그리고 "쪼개서 배정하자" 말풍선이 보여주는 위임 장면. 그래서 위임이 일어나면 직원이 층과 책상 사이를 걸어 다니는 연출이었을 것으로 봄.
- 참고로 헤르메스 생태계에는 "Hermes Pixel Office"(Teknium/Nous 쪽으로 소개되지만 2차 출처만 있음)가 있음. 동작은 이렇게 소개됨: 문으로 들어와 책상에 앉음, 파일 쓰기는 타이핑, 읽기는 책 펼치기, 터미널은 모니터가 초록으로 깜빡임, 승인이 필요하면 머리 위에 빨간 "!", 끝나면 일어나서 문으로 나감, 서브에이전트는 금색 칼라와 이름표, 화면 위쪽에 "2 waiting" 카운터. 강의의 "픽셀풍 화면"이 이 계열을 참고했을 수 있음(추론). 출처: https://juliangoldie.com/hermes-pixel-office/

**공통 패턴 정리**
1. **위치로 상태를 먼저 알림**: 책상 = 일하는 중, 소파 = 쉬는 중, 회의실 = 협업, 대표석 = 승인.
2. **포즈와 소품으로 도구 종류를 알림**: 타이핑, 책, 모니터 깜빡임, 돋보기.
3. **머리 위 기호는 주의가 필요한 상태에만**: 승인 대기 "!", 오류 "⚠".
4. **말풍선에는 지금 하는 단계를 짧게** 적고 자동으로 사라지게 함.
5. **주의가 필요한 상태는 화면 위쪽 카운터로 모아 보여줌.** 사운드는 선택 사항이고 기본은 끔.
6. **걷는 연출은 의미 있는 이벤트에만 씀**: 출근, 위임, 승인 요청, 완료 보고. 아무 이유 없이 돌아다니는 건 idle일 때만, 드물게.
7. **이벤트로 움직이고, 가끔 한 번씩 재동기화**함.

## 3. 권장안: 직원 13명(개발 6 + 비즈니스 7) 사무실

현재 앱의 직원 명단(`src-tauri/src/roster.rs`)을 그대로 씀.
- 개발팀(`DEV_TEAM`): 태오(테크 리드), 유나(프론트엔드), 건우(백엔드), 소희(QA), 민혁(코드 리뷰어), 다은(테크 라이터)
- 비즈니스: 하린(블로그 작가), 지호(숏폼 작가), 서진(자료조사원), 민재(영업 개척), 도윤(견적), 수아(사무 정리), 예나(지원사업 분석)

### 3-1. 레이아웃
레퍼런스와 가장 닮게 **3층 측면 단면도**를 권장함. 논리 해상도는 1280×720으로 잡고 화면에 맞게 확대/축소함.

```
┌─────────────────────────────────────────────────────────┬──┐
│ 3F 개발실 (청록 벽)  [태오][유나][건우][소희][민혁][다은] 화이트보드 │계│
├─────────────────────────────────────────────────────────┤단│
│ 2F 비즈니스 오피스  콘텐츠[하린][지호] 리서치[서진] 영업[민재]       │/ │
│   (팀 색 파티션)     경영지원[도윤][수아][예나]                     │엘│
├─────────────────────────────────────────────────────────┤리│
│ 1F  ☕라운지(소파·커피머신) │ 회의실(테이블) │ 대표석+결재함·결과함 │ 문 │베│
└─────────────────────────────────────────────────────────┴──┘
                                    + 오른쪽 패널: "실시간 업무 채널"(events 로그)
```
- 층은 팀 단위로, 벽과 명찰 색은 팀 색으로 맞춤(메이크패밀리 방식). 옷 색은 직원별 `hue`를 씀.
- 1층 구역:
  - **라운지**: idle 상태, 쉬는 중
  - **회의실**: 팀 프로젝트 시작이나 위임 회의
  - **대표석**: 사용자 자리. 승인 대기 줄과 결과물 받는 곳
  - **문**: 앱을 켤 때 출근 연출
- 층을 오갈 때는 오른쪽 계단 또는 엘리베이터 노드를 지남. 경로는 웨이포인트 그래프 하나면 충분함. 예: `desk → floor-exit → stairs → floor-entry → target`.

### 3-2. 앱 상태가 연출로 바뀌는 매핑
기준은 `models.rs`의 status(queued / awaiting_approval / running / paused / completed / failed / cancelled)와 step의 `actor`, `gate`.

| 앱 상태 / 이벤트 | 어디로 가는가 | 포즈 / 애니메이션 | 머리 위 칩 | 말풍선 예시 | 추가 연출 |
|---|---|---|---|---|---|
| 업무 없음 (idle) | 자기 책상. 30~90초마다 확률적으로 커피머신·창가·라운지에 다녀옴 | 앉아서 숨쉬는 동작, 기지개, 폰 보기 | 없음. 오래 쉬면 💤 | (선택) 잡담 한 줄 | 채도를 조금 낮춤 |
| queued | 책상 | 서류 트레이에 종이가 한 장 놓임 | 회색 "대기 #2" | "곧 시작할게요" | — |
| running · step 시작 | 책상으로 걸어가서 앉음 | 기본은 **타이핑** | 초록 "작업 중" | 단계 이름, 예: "초안 작성 중…" | 모니터에 빛, 진행률 바 |
| ├ 조사 단계 (collect / research / scan) | 책상 또는 책장 | 책이나 문서를 넘김 | 〃 | "자료 수집 중…" | 📚 소품 |
| ├ 실행 단계 (test / build / apply) | 책상 | 모니터가 초록으로 깜빡임 | 〃 | "테스트 실행 중…" | 터미널 글자 효과 |
| └ 리뷰 단계 (review) | 책상 | 의자를 젖히고 돋보기 | 〃 | "코드 리뷰 중…" | 🔍 |
| **핸드오프** (step의 actor가 바뀜, 예: 태오가 유나에게 frontend) | 위임하는 사람이 폴더를 들고 받는 사람 책상까지 걸어가서 건네고 돌아옴 | 건네기 동작, 받는 쪽은 고개 끄덕 | 들고 가는 동안 📁 | "유나 님, 화면 개발 부탁해요" / "넵!" | 점선 연결선이 1초 보였다 사라짐 |
| 팀 프로젝트 시작 (태오의 plan 단계) | 관련 팀원이 1층 회의실에 모임. 끝나면 흩어짐 | 테이블에 둘러앉음 | — | "구조부터 정할게요" | 화이트보드에 낙서 |
| **awaiting_approval** (gate: apply / merge) | 결재 서류를 들고 1층 대표석 앞에 **줄을 섬** | 서서 발을 동동 구름 | 주황/빨강 **"!" 깜빡임** | gate 제목 | 위쪽 HUD에 "승인 대기 N", 결재함 배지, 차임(선택). 클릭하면 승인 창 |
| 승인됨 | 도장 효과 후 책상으로 돌아가 실행을 이어감 | 꾸벅 인사 | ✓ (1.5초) | "감사합니다!" | — |
| paused | 책상 | 팔짱을 끼고 멈춤 | ⏸ | "잠시 멈춤" | 채도 낮춤 |
| **completed** | 결과물을 대표석 "결과함"에 놓고 책상이나 라운지로 감 | 작게 점프하거나 손 흔들기 | ✅ (3초) | "완료! 결과 확인해 주세요" | 결과함 배지 +1, 프린터 동작 |
| failed | 자기 책상에 그대로 있음. 다른 곳에 보내면 누가 실패했는지 헷갈림 | 머리를 감싸 쥠, 모니터가 빨갛게 | 빨강 "⚠" | 오류 요약 한 줄 | 클릭하면 로그. (선택) 태오나 소희가 와서 들여다봄 |
| cancelled | 서류를 휴지통에 버린 뒤 idle로 | — | 회색 | "취소됐어요" | — |
| 한 직원이 업무 여러 개 | 가장 우선순위가 높은 업무 기준으로 표시 | — | 칩에 "+2" | — | — |
| 앱 시작 | 문에서 한 명씩 입장(150ms 간격)해서 자리에 앉음 | 걷기 | — | — | 처음 한 번만 |
| 시간대 | — | — | — | — | 창밖이 실제 시간에 맞춰 낮/밤으로 바뀜(메이크패밀리의 해/달 메타포). 밤에는 일하는 사람 책상 조명만 켬 |

**표시 우선순위**: awaiting_approval > failed > running > queued > completed(3초간) > paused > idle

## 4. 구현 팁 (React + Tauri)

**렌더링**
- 13명 규모면 **DOM/SVG + CSS transform**으로 충분함. OpenClaw Office가 같은 방식(React+SVG)임. Canvas는 50명 이상이거나 파티클이 많을 때 고려.
- 캐릭터 하나 = `position:absolute`인 `<div>` + `transform: translate3d()`.
- 걷기 동작은 SVG 파츠(팔·다리)에 CSS keyframes를 걸거나, 스프라이트에 `steps()`를 씀. 방향은 `scaleX(-1)`로 좌우 반전.

**루프와 상태 분리**
- React state에는 논리 상태만 둠: 목표 구역, 좌석, status, 말풍선.
- `requestAnimationFrame` 루프 하나에서 등속(약 70px/s)으로 위치를 보간하고, **ref로 `style.transform`을 직접 씀.** 매 프레임 React를 다시 렌더링하지 않기 위해서임.
- `document.hidden`이거나 창이 최소화되면 루프를 멈춤.

**이벤트 흐름**
- Tauri `task-updated` 이벤트(`runner.rs`의 `emit`) → task와 events 조회 → 직원별 시각 상태를 reducer로 계산.
- 30~60초마다 전체 목록을 한 번 다시 맞춤(OpenClaw 방식).
- **직원마다 연출 큐를 둠**: 걷기 → 건네기 → 복귀 순서를 지키게 하려는 것. 큐가 3개를 넘으면 중간 단계는 건너뛰고 마지막 상태로 바로 맞춰서 순간이동처럼 보이는 일을 막음.
- **최소 표시 시간**을 둠: 말풍선 2.5초, 완료 칩 3초. step이 빨리 지나가도 사용자가 볼 수 있게 하려는 것.

**말풍선**
- 18자 정도에서 말줄임 처리.
- 같은 층에서 이웃한 말풍선은 높이를 번갈아 배치.
- 동시에 3개가 넘으면 우선순위가 낮은 것부터 숨김.

**상호작용**
- 캐릭터 클릭 → 해당 업무 상세(WorkPage)
- 대표석 클릭 → 승인 대기 목록
- 마우스를 올리면 툴팁: 현재 단계, 경과 시간
- 오른쪽에 메이크패밀리식 **"실시간 업무 채널" 패널**(db events 로그)을 붙이면 레퍼런스 화면 구성과 가장 비슷해짐.

**배율**
- 논리 해상도(1280×720) 스테이지 전체에 `transform: scale()`를 걸어 화면에 맞춤.
- 픽셀풍으로 갈 경우 정수 배율 + `image-rendering: pixelated`.

**접근성과 설정**
- `prefers-reduced-motion`이면 걷기 대신 페이드로 자리를 옮김.
- 사운드와 idle 배회는 설정에서 켜고 끌 수 있게 함.

**아트**
- 원본 에셋을 쓰지 말고 직접 만듦. 예: 2.5등신 플랫 SVG 치비, 4~6색 팔레트, 팀 색 명찰.
- LimeZu, Metro City 계열은 상업 이용 제한이 있으니 쓰지 말 것(Star Office UI 아트도 상업 이용 금지).
