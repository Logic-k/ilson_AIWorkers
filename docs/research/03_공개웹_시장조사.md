# AIMAX (aimax.ai.kr) 공개 웹 리서치 보고서

- 조사일: 2026-10-13
- 대상: "AIMAX - 사장님 대신 일하는 AI 직원" (운영: 주식회사 메이크패밀리, 대표 윤동규)
- 방법: 공개 페이지 열람(WebFetch/curl), 웹 검색, 공개 GitHub 저장소의 텍스트 문서와 메타데이터 열람. 로그인, 회원가입, 구매, 폼 제출, 실행 파일 다운로드는 하지 않았다.
- 표기:
  - **[관찰]** 출처 페이지나 소스에서 직접 확인한 사실
  - **[추론]** 관찰을 근거로 한 해석
  - **[미확인]** 찾지 못했거나 확인할 수 없었던 사항
- 동명 제품 주의: 한국후지필름BI도 기업용 RAG 에이전트 "AIMAX"를 판매한다 ([후지필름 보도자료](https://www.fujifilm.com/fbkr/ko/news/list/press-release/2026/06/ai-success-case-seminar)). 이 제품은 메이크패밀리 AIMAX와 무관하며, 아래 내용에는 포함하지 않았다. "AIMAX"로 웹을 검색하면 대부분 후지필름 결과가 나온다.

## 0. 핵심 요약

1. **[관찰]** AIMAX는 소상공인을 위한 "AI 직원" 제품군이다. 직원별로 카페24 쇼핑몰(makefamily.kr)에서 1회 30,000원에 판다. 구매자는 웹 콘솔(api.aimax.ai.kr/app) 계정을 받고, 필요하면 PC 실행기를 설치한다. ([aimax.ai.kr](https://aimax.ai.kr), [스토어 카테고리](https://makefamily.kr/product/list.html?cate_no=85))
2. **[관찰]** 기술 구조는 하이브리드다.
   - 웹 콘솔: 단일 HTML, vanilla JS
   - 서버: Node.js 단일 파일, Oracle Cloud, JSON 파일 저장
   - 로컬 실행기: Python, Selenium/undetected-chromedriver. Chrome으로 네이버 블로그 SmartEditor를 자동 조작한다(예리 글쓰기, 현주 서로이웃 신청).
   - 연결: 웹 콘솔이 `aimax://` 커스텀 프로토콜로 실행기를 깨운다. 실행기는 서버 작업 큐를 polling한다.
   - 출처: [콘솔 HTML](https://api.aimax.ai.kr/), 공개 저장소 [aixlife/AIMAX-AI-Staff-Management](https://github.com/aixlife/AIMAX-AI-Staff-Management)
3. **[관찰]** AI 비용은 BYOK(사용자 키) 방식이다. 사용자가 Gemini, OpenAI, Claude, Apify, YouTube 키를 콘솔의 "AI/API 연결"에 등록한다. 유료 호출은 실행 전에 비용 확인창으로 승인을 받는다. 네이버 ID/비밀번호는 로컬 실행기에만 저장된다. ([콘솔](https://api.aimax.ai.kr/app))
4. **[관찰]** "AI 직원" 중 일부만 AI 에이전트다.
   - AI 에이전트: 예리, 현주, 윤미, (송이)
   - AI 호출 없는 유틸리티: 상수(견적서), 나경(판서), 맥스(알람), 지은(캡처/OCR), 은서(프롬프터)
   - 외부 파트너 서비스로 링크만 연결: 송이(훔쳐봐), 지원(딱, 지원핏)
5. **[관찰]** 독립 리뷰, 뉴스, 블로그 후기는 거의 없다. 외부에서 확인되는 것은 패스트캠퍼스 강의 페이지와 강사 인터뷰, 유튜브 채널(구독자 1.6만) 정도다. 스토어 리뷰 게시판은 모두 "게시물이 없습니다"였다.
6. **[관찰]** 운영사의 메인 소스 저장소가 **public이고 라이선스가 없다**. 2026-10-13 기준 오늘도 push가 있었다. 아키텍처 문서, 운영 기록, 파트너 협약 초안까지 공개돼 있다. [추론] 의도하지 않은 공개일 수 있다. 라이선스가 없으므로 코드 재사용 권리는 없다(참고만 가능).

### 2.3 "AI 직원" 연출 방식

- **[관찰]** 직원마다 입사지원서 형식의 가상 프로필이 있다. 사번(예: "AIMAX-2026-YERI"), 소속 팀, 경력 연차, 고향, 전 직장, 추천사, 스킬 점수(5점 만점)로 구성된다. aimax.ai.kr은 "이름과 사진은 역할을 친숙하게 이해하도록 만든 가상의 AI 직원 설정"이라고 고지한다. ([콘솔 HTML](https://api.aimax.ai.kr/), [aimax.ai.kr](https://aimax.ai.kr))
- **[관찰]** 직원 상태 배지 종류: 사용 가능, 설정 필요, 권한 없음, 발령 대기, 검수 중, 미지원. 실행 방법 필터: "전체 웹에서 바로 사용", "PC 설치형", "모바일/토스". ([콘솔](https://api.aimax.ai.kr/app))
- **[관찰]** "AIMAX Brain"이라는 기능도 노출된다. 설명은 "회사 지식, 직원 역할, 작업 결과가 연결되는 뇌 지도 미리보기"이고, 현재는 미리보기 영상만 있다.

### 4.2 작업 흐름

**[관찰]** 아래 흐름은 [서버 README](https://github.com/aixlife/AIMAX-AI-Staff-Management/blob/main/oracle/aimax-reports-api/README.md)와 콘솔 JS(`launchLocalAgent`, `waitForAgentCommand`)에서 확인했다.

```
[웹 콘솔] 업무지시 폼 → POST /api/jobs (예: yeri_write)
   │  (유료 호출이면 402 *_paid_confirmation_required → 비용 확인창 → 재요청)
   ▼
[서버] jobs.json 큐 ─────────────── GET /api/agent/next-job (실행기가 polling, 가져가면 즉시 running, 24h 리스)
   │                                   ▲
   │ 실행기 미연결 시: window.location = "aimax://agent/connect?account=<email>"
   ▼                                   │
[로컬 실행기] Chrome 기동(undetected-chromedriver/Selenium) → 네이버 로그인 → SmartEditor 열기
   → 제목/글꼴/본문 입력 → 이미지 생성·업로드 → 임시저장/발행/예약 → POST /api/agent/jobs/update
   (heartbeat: POST /api/agent/heartbeat, 원격 명령: /api/agent/next-command)
```

- **[관찰]** 콘솔에 정의된 실패 단계 코드
  - 흐름: `content_generation`, `browser_start`, `naver_login`
  - 에디터: `smart_editor_open`, `_title`, `_font`, `_input`, `_save`, `_publish`, `_schedule`
  - 이미지: `image_generation`, `image_upload`, `image_insert_exception`
  - 이 목록으로 보아 네이버 SmartEditor를 DOM 단계별로 조작하는 구조다. ([콘솔 HTML](https://api.aimax.ai.kr/))
- **[관찰]** `config.yaml`의 동작 파라미터 ([config.yaml](https://github.com/aixlife/AIMAX-AI-Staff-Management/blob/main/config.yaml))
  - 사람처럼 보이게 하는 지연값: 타이핑 평균 0.05초, 동작 평균 1.5초, 글 사이 10초
  - 세션당 공감 30개, 댓글 15개
  - 네이버 에디터 CSS 셀렉터를 설정 파일에서 덮어쓸 수 있다("네이버 업데이트 시 여기만 수정").
- **[관찰]** `neighbor_quota.py` 주석: "네이버 공식 한도는 하루 100명(2026-04 기준). 공식 한도보다 보수적으로 설정". ([neighbor_quota.py](https://github.com/aixlife/AIMAX-AI-Staff-Management/blob/main/engagement/neighbor_quota.py))
- **[관찰]** 보안 원칙(로드맵): "서버에는 네이버 비밀번호, 쿠키, 세션 원문을 저장하지 않는다", "완전 무설치 SaaS를 1차 목표로 두지 않는다". 콘솔 안내: "네이버 ID와 비밀번호는 기존처럼 내 PC의 로컬 실행기에만 저장됩니다. 웹 서버로 보내지 않습니다." ([로드맵](https://github.com/aixlife/AIMAX-AI-Staff-Management/blob/main/docs/aimax_update_roadmap.md), [콘솔](https://api.aimax.ai.kr/app))
- **[관찰]** AI/API 키는 처음에 실행기 로컬 설정에 저장했다. 지금은 "웹 보안 저장소"(서버 `user-secrets.json`, 암호화)로 옮겼고, 콘솔에 "기존 실행기 키 가져오기" 명령(`import_local_provider_secrets`)이 있다. ([콘솔 HTML](https://api.aimax.ai.kr/))

### 8.2 공통 패턴 [추론, 위 출처 종합]

1. **페르소나화**: 이름, 얼굴, 직무, (때로는) 이력서나 성격을 붙인다. 기능 묶음을 "채용" 메타포로 판다(AIMAX, Sintra, Marblism, Motion).
2. **업무 지시 UX**: 직원별 정형 폼(AIMAX: 키워드, 스타일, 발행 모드, 모델) 또는 채팅. 결과는 "작업 기록", "미리보기"로 보여준다.
3. **승인 게이트**: 발송, 발행, 비용 발생 전에 사람이 승인한다. Marblism은 "drafts but doesn't send", Relevance AI는 도구별 승인 모드, AIMAX는 유료 호출 확인창과 세금계산서 "발행 준비 → 발행" 단계를 쓴다.
4. **공유 메모리 / 세컨드 브레인**: Sintra Brain AI, Genspark Second Brain, AIMAX Brain(미리보기), 메이크패밀리 강의의 LLM Wiki.
5. **연동**: 글로벌 제품은 SaaS API 연동 수백~수천 개를 내세운다. API가 없는 대상은 브라우저나 데스크톱 에이전트로 처리한다(Lindy computer use, AIMAX의 네이버 로컬 실행기).
6. **과금**: 글로벌 제품은 월 구독에 크레딧이나 시간 풀을 붙인다. AIMAX는 직원별 1회 구매(30,000원)에 BYOK 사용료를 따로 내는 구조다. 국내 블로그 자동화 툴은 PC 프로그램 판매가 많다.

### 8.3 AIMAX의 차별점과 약점 [추론]

**차별점**
- 한국 소상공인 특화(네이버 블로그, 서로이웃, 정부지원사업, 세금계산서).
- 저가 1회 구매.
- 네이버처럼 공식 API가 없는 대상을 사용자 PC에서 자동화하므로 서버에 자격 증명을 두지 않는다.
- 교육 커뮤니티(AI사장학교, 패밀리회원)와 묶어 판다.
- 수강생 서비스를 입점시킨다.

**약점**
- "직원" 다수가 단순 유틸리티이거나 외부 링크다.
- 핵심 AI 직원(예리, 현주)이 네이버 UI 변경과 봇 탐지에 취약하다. 실패 단계 코드가 세분화돼 있고 안정화 공지가 있었던 것이 그 근거다.
- 웹 콘솔, 설치형 실행기, 위성 앱(Electron/Tauri), 파트너 사이트로 사용자 경험이 나뉜다.

## 9. 시사점과 리스크 (오마주/유사 제품 기획 관점)

1. **네이버 자동화 정책 리스크** [추론]
   - AIMAX는 `undetected-chromedriver`와 `selenium-stealth`, 사람 같은 지연값으로 탐지를 피하는 방식을 쓴다.
   - 자동 서로이웃, 공감, 댓글은 네이버 운영정책 위반이나 저품질 처리 가능성이 거론되는 영역이다.
   - 네이버 공식 정책 원문은 이번 조사에서 확인하지 못했다([미확인]). ([검색 결과 요약: bizhankook](https://www.bizhankook.com/bk/article/29309), [promptcorelab](https://promptcorelab.com/naver-blog-ai-automation-workflow/))
2. **라이선스** [관찰]
   - `aixlife/AIMAX-AI-Staff-Management`, `makefriendscoltd-design/*` 저장소는 public이지만 license가 `None`이다. `ai-os`는 `"license": "UNLICENSED"`다.
   - [추론] 코드나 문서를 복제·재배포할 권리가 없다. 구조와 아이디어 참고는 가능하지만 코드 이식은 피해야 한다.
3. **공개 저장소의 민감성** [관찰]
   - 운영 문서, 서버 IP, 관리자 API 목록, 파트너 협약 초안 같은 운영 정보가 공개돼 있다.
   - [추론] 의도하지 않은 노출일 수 있다. 이번 조사에서 비밀값(.env 등)을 찾으려 하지 않았고, 그런 내용을 재배포하면 안 된다.
4. **환불·업데이트 문구 불일치**
   - 스토어는 "환불 불가", 라운지는 "7일 내 미사용 전액 환불"이다.
   - [추론] 유사 서비스를 만든다면 판매 페이지와 약관을 하나의 정본으로 맞춰야 한다.
5. **아키텍처 참고점** [추론]
   - 웹 콘솔, 작업 큐, 로컬 에이전트 polling, 커스텀 URL 프로토콜로 구성된 분리 구조가 있다.
   - 유료 호출 402 게이트와 비용 사전 표시, 직원 카탈로그(`execution`: `local_agent` / `web_module` / `desktop_app` / `partner_external`), 실패 단계 코드 기반 오류 보고는 참고할 만한 패턴이다.
   - 반대로 단일 파일 서버와 JSON 파일 DB는 회사 스스로 문제로 지적한 부분이다.
