# 일손 — AI 코딩 회사

이름 있는 AI 직원들이 사장님의 **구독**(Antigravity · Claude Code · Codex · Kiro)으로 일하는 데스크톱 앱입니다. **API 키는 받지도, 쓰지도 않습니다.**
업무를 맡기면 직원들이 한 작업 공간에서 설계 → 개발 → 테스트 → 리뷰를 주고받고, 그 모습이 건물 단면도 사무실에서 실시간으로 보입니다.

AIMAX(aimax.ai.kr)의 "AI 직원 인력사무소" 방식을 REA로 분석해 참고했고, 코드·이미지·문구는 쓰지 않고 Tauri 2 + Rust + React로 새로 만들었습니다. 직원 이름과 이력은 모두 가상입니다.

- 분석 보고서: [docs/AIMAX_REA_분석보고서.md](docs/AIMAX_REA_분석보고서.md)
- 구독 엔진·YOLO 키워드 조사: [docs/구독엔진_YOLO_키워드.md](docs/구독엔진_YOLO_키워드.md)

## 직원

**개발팀 (3층)** — 코드를 만들고, 사장님이 병합을 눌러야만 원래 저장소에 반영됩니다.

| 직원 | 역할 | 하는 일 |
|---|---|---|
| 태오 | 테크 리드 | 요청을 설계하고 팀원에게 나눠 맡겨 팀 프로젝트로 진행 |
| 유나 | 프론트엔드 | 화면 구현 → 민혁 리뷰 → 병합 대기 |
| 건우 | 백엔드 | 서버·로직 구현 → 민혁 리뷰 → 병합 대기 |
| 소희 | QA | 테스트 작성·실행, 버그 보고 |
| 민혁 | 코드 리뷰어 | 변경 리뷰와 통과/수정 필요 판정 (코드는 고치지 않음) |
| 다은 | 테크 라이터 | README·설명서 정리 |

**사무팀 (2층)** — 하린(블로그 초안), 지호(숏폼 대본), 서진(자료조사), 민재(영업 후보), 예나(지원사업 공고 점검)는 AI로, 도윤(견적서)·수아(폴더 정리)는 AI 없이 이 PC에서 일합니다.

## 구독 엔진과 실행 방식

| 엔진 | 구독 | 앱 자동 실행 |
|---|---|---|
| Antigravity CLI (`agy`) | Google AI | 가능 |
| Claude Code (`claude`) | Claude Pro/Max | 가능 |
| Codex CLI (`codex`) | ChatGPT Plus/Pro | 가능 |
| Kiro CLI (`kiro-cli`) | Kiro | 안전 모드만 |

- **직원별 담당 구독:** 연결 및 설정에서 직원마다 엔진을 고릅니다. 같은 업무 안에서도 단계마다 담당 직원의 구독으로 일하고 다음 사람에게 넘깁니다.
- **안전 모드(기본):** 앱이 지시서(`.ilson/TASK.md`)와 에이전트 정의(Antigravity `.agents/agents/`, Claude Code `.claude/agents/`)를 준비하면, 사장님이 Antigravity나 터미널에서 직접 실행합니다. 앱은 직원들이 남기는 상태·보고서 파일과 git 변경을 지켜보다가 다음 단계로 넘깁니다.
- **자동 모드:** 엔진마다 위험 안내에 동의한 엔진만 앱이 헤드리스로 실행합니다. 동의하지 않은 엔진의 차례에서는 그 단계만 안전 모드로 바뀝니다. Google·Anthropic 약관상 앱이 구독 CLI를 감싸 실행하는 방식에는 계정 위험이 있어 기본값은 꺼져 있습니다(자세한 내용은 조사 문서).
- **YOLO 모드:** 자동 모드에서 파일을 고치는 단계의 모든 확인을 생략합니다. `agy`/`claude`는 `--dangerously-skip-permissions`, `codex`는 `--dangerously-bypass-approvals-and-sandbox`를 씁니다.

## 일하는 원칙

1. **API 키 0개** — 실행할 때 API 키 환경 변수를 지우고, API 키로 로그인된 CLI는 쓰지 않습니다. 로그인 상태 확인은 사용량을 쓰지 않습니다.
2. **내 저장소는 확인 후에** — 개발팀은 업무마다 앱 데이터 폴더의 별도 git worktree에서 일합니다. 사장님이 변경 내용(diff)을 보고 "병합하기"를 눌러야 원래 브랜치에 `--no-ff`로 합쳐지고, "작업 공간 지우기"로 흔적 없이 정리할 수 있습니다.
3. **멈춰도 이어서** — 단계마다 결과를 SQLite에 저장해, 앱을 꺼도 끝낸 단계 다음부터 이어 합니다.
4. **반복 오류 가드** — 같은 직원이 같은 이유로 두 번 연달아 실패하면 "조치했어요"를 누를 때까지 새 업무를 막습니다.
5. **파일 정리는 이동만** — 수아는 계획을 먼저 보여 주고 확인을 받은 뒤 옮기며, 언제든 되돌릴 수 있습니다.

## 실행

필요: Node.js 20+, Rust(stable), Git, Windows는 WebView2(Windows 11 기본 포함). 그리고 위 구독 CLI 중 하나 이상.

```bash
npm install
```

```bash
npm run tauri dev
```

배포용 설치 파일(Windows는 NSIS `.exe`, `src-tauri/target/release/bundle/nsis/`):

```bash
npm run tauri build
```

처음 실행하면 **연결 및 설정**에서 각 엔진의 로그인 상태를 확인하고(필요하면 "로그인 창 열기"), 직원별 담당 구독을 고르세요.

## 구조

```
src-tauri/src/
  engine.rs    구독 CLI 실행: 찾기, 로그인 확인, 권한 단계(읽기/편집/샌드박스/YOLO), 엔진별 출력 해석
  gitops.rs    업무별 git worktree, 커밋(관리용 파일 제외), diff, 병합·정리
  workers.rs   직원별 단계: AI 작업 계획(AiJob), 안전 모드 지시서·관찰, 자동 실행, 견적·파일 정리
  runner.rs    업무 실행기: 단계 순회, 확인 게이트(병합·파일 이동·직접 실행), 멈추기·이어하기
  roster.rs    직원 명부: 페르소나, 업무 폼, 단계와 담당 직원(actor)
  db.rs        SQLite: 업무·단계 체크포인트·기록·가드
  commands.rs  화면에서 부르는 Tauri 명령
src/
  components/OfficeScene.tsx   3층 사무실 단면도와 직원 이동 시뮬레이션
  pages/                       사무실 · 홈 · AI 직원 · 업무 · 연결 및 설정 · 도움말
```

데이터 위치: `%APPDATA%\kr.ilson.desktop\` (업무 DB `ilson.db`, 작업 공간 `worktrees\`, 사무팀 실행 폴더 `runs\`).

## 하지 않는 일

- 블로그 자동 발행, 이웃 신청·DM 자동 발송
- 비공개 개인 연락처 수집
- 로그인 토큰 읽기·추출, API 키 사용
- 사장님 확인 없는 원래 저장소 변경, 파일 삭제
